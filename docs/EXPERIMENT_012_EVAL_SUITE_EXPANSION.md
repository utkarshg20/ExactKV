# Experiment 012: V10 Evaluation-Suite Expansion

_Generated by `scripts/run_experiment_012_eval_suite_expansion.py`. V10 Phase 2 — evaluation-suite expansion only._

> This is **evaluation-suite expansion**, not a performance benchmark.
> The V10 suites are **stronger and more diverse** than the old 34-prompt `core` suite, but are **still not a universal benchmark**.
> ExactKV preserves the exactness gate: `exactkv_output_ids == full_output_ids`.
> Simulated compressors (`_sim`) are **not** real packed-bit backends.
> `total_kv_footprint_bytes` is a conservative accounting sum, **not** measured peak GPU memory.
> **Active GPU memory is not reported.**
> ExactKV does **not** claim speedup, throughput, latency, runtime, tokens/sec, active GPU memory, or production readiness.

---

## 1. Purpose

Run the full V10 prompt panel (128 prompts across seven versioned suites) against the standard built-in compressor panel to produce **global and per-category acceptance leaderboards**, prompt-level win/loss analysis, and exactness validation on a stronger evaluation set than Experiments 002–011 (`core`, 34 prompts).

## 16. What this proves

- The exactness gate holds on **128 × 7 = 896** cells across diversified V10 suites.
- Acceptance rankings can be reported **per suite** and **per category**, not only as a single global mean.
- Layer-aware boundary4 vs uniform k8_v4_sim and int8 vs boundary4 relationships can be examined prompt-by-prompt on a harder panel.

## 17. What this does not prove

- That V10 suites are a comprehensive universal public benchmark.
- Production serving behaviour, throughput, or latency.
- That `_sim` compressors achieve real packed-bit memory savings.
- That external paper results (TurboQuant, KIVI, KVQuant) apply to these cells.

## 18. Limitations

- Single model (0.5B), single `draft_len`, single `max_new_tokens`.
- Some `core_v2` categories have low prompt counts (flagged above).
- No restricted real backends in this experiment (factory-only adapters deferred).
- Category labels are author-assigned taxonomy, not tokenizer-derived.

## 19. Relation to Experiment 013

Experiment 013 (Phase 3) will sweep `draft_len` and `max_new_tokens` and deepen divergence forensics on `core_v2` (or a stratified subset). Experiment 012 establishes the expanded-suite baseline at anchor settings.
