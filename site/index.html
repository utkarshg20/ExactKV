Empirical findings

Four things ExactKV established

Across Llama-3.1-8B and Mistral-7B, five benchmark families, five compressor variants.

01

Task type dominates drift

The same int4_sim compressor on the same model diverges at wildly different rates depending on task type.

02

On BFCL, int4_sim divergence grows with output budget — same task, same context, different generation length.

Mechanistic analysis

Three compressor classes, three failure signatures

Top-k logit autopsy over 1,103 divergent cells — full top-5 logit traces at first divergence.

int8 Near-tie noise

Small quantization errors perturb logits at decision boundaries where the top-2 tokens are nearly tied. The flip is random-looking — whichever side of the boundary the rounded value falls on.

66%
near-tie rate
2.4
mean lossy rank
22
median fdi

Divergence is late and recoverable. The draft stays useful before divergence — high acceptance rate up to fdi≈22.

int4_sim Distribution shift

Aggressive per-tensor quantization biases activation distributions, systematically shifting probability mass toward lower-ranked alternatives. Not a tie — the full-KV winner is demoted to rank 3–4.

83%
top-1 flip rate
3.5
mean lossy rank
8
median fdi

Earlier divergence than int8 (fdi≈8). The correct token is still in the top-5 — just not top-1. Systematic rather than random.

h2o_sim Attention destruction

Token eviction removes contextual anchors entirely from the KV cache. The model loses track of long-range dependencies — the correct token isn't in the top-5 at all. Divergence happens at token 1.

100%
top-1 flip rate
6.7
mean lossy rank
1
median fdi

Catastrophic. Divergence at the first generated token — the compressed draft is essentially unusable on long-context reading tasks.

The same ExactKV verifier corrects all three failure modes. exactkv_failures = 0 across all 7,348 cells — including every 100%-divergent H2O cell. Drift and exactness failure are not the same thing.

Compression curve

Granularity outweighs bit-width

Two new compressors extend the curve — one per-tensor, one per-vector (KVQuant/KIVI-style).

Compressor Granularity MAE Error ×int8 Theoretical ratio Status
int8 per-tensor 0.067 1.00× 0.50× fp16 GPU validated
int6_sim per-tensor 0.275 4.10× 0.375× fp16 v3.0 panel
int4_per_vec_sim per-vector 0.138 2.06× 0.25× fp16 v3.0 panel
int4_sim per-tensor 0.844 12.59× 0.25× fp16 GPU validated
Key insight: int4_per_vec_sim (4-bit per-vector) has 6× lower quantization error than int4_sim (4-bit per-tensor) at the same memory budget. Per-vector granularity eliminates cross-head contamination from outlier attention heads. KV tensors with outlier heads are the norm in 7–8B models.

MAE measured on realistic KV shape [1, 32, 512, 64] with simulated outlier heads (first 4 heads 5× larger). int6_sim and int4_per_vec_sim are simulations stored as fp16. GPU drift panels completed for Mistral-7B (v3.0); Llama-3.1-8B pending. Inspired by per-vector/per-channel granularity in KVQuant and KIVI.

How it works

Draft / verify / commit loop

1
Draft

Generate tokens autoregressively from the compressed KV cache.

→
2
Verify

Compare each draft token against the full-KV reference (greedy argmax).

→
3
Accept or correct

Accept the matching prefix. On mismatch: emit the full-KV token, log the divergence event.

→
4
Record

Log first_divergence_index, acceptance_rate, exactkv_failure per cell.

first_divergence_index

First token where compressed KV greedy output ≠ full-KV. Phase G canonical authority.

acceptance_rate

Fraction of drafted tokens accepted before the first mismatch. Draft-utility proxy.

exactkv_failure

Final ExactKV output ≠ full-KV greedy. Hard gate: 0 on all tested panels.

compression_ratio

Stored tensor byte ratio. Not active GPU memory savings.

Claim boundaries

What ExactKV does and does not claim

yes

Measures token-level drift for built-in compressors on tested panels

yes

Reports first-divergence index, acceptance rate, and exactness failures per cell

yes

Identifies mechanistic failure modes via top-k logit autopsy

yes

Preserves downstream BFCL tool-call validity via verifier correction

no

Not a production serving system; does not claim end-to-end throughput improvements

no

Does not reproduce VeriCache; not an implementation of VeriCache semantics

no

Phase F kernel ratios are microbenchmarks only — not end-to-end speedup

no

Reproducibility

Reproduce it

Every published number traces to an on-disk artifact. One-command regeneration.

No GPU — verify artifacts

python3 scripts/exactkv_repro.py --reports-only
python3 scripts/exactkv_repro.py --release-check
bash scripts/build_paper_pdf.sh   # requires tectonic

GPU — headline panel

python3 scripts/run_phase_a_scale_benchmark.py \
  --device cuda --dtype float16

GPU — v3.0 new compressors

bash scripts/run_v30_new_compressors.sh
python3 scripts/summarize_v30_panel.py \
  --output reports/external_panels/v30/summary.md
